## Exact APIs inspected in the installed release

Authority must be identical on all peers before synchronization. Player root
belongs to peer 1; its `Input` child belongs to `owner_peer_id`. Configure
`RollbackSynchronizer.root`, `state_properties` and `input_properties` using
ordered paths (`:position`, `:velocity`, `Input:movement`, etc.). Call
`process_settings()` **after the synchronizer enters the tree**: composition
objects do not exist before `_enter_tree`. `process_settings()` calls
`process_authority()` and clears states, inputs, and freshness, so do not call
it every tick or use it casually to respawn a still-live actor.

- `enable_input_broadcast = false` sends input only to the state-owning server.
  Enable prediction for the local owning client, not for remote clients without
  inputs; decide server gap prediction explicitly and limit stale input.
- Controller entry point: `_rollback_tick(delta: float, tick: int, is_fresh: bool)`.
  No duplicate movement in `_physics_process`. For `move_and_slide`, multiply
  velocity by `NetworkTime.physics_factor` first and divide afterwards. With
  network and physics both 30 Hz in a physics frame, that factor is 1.
- `has_input()`, `get_input_age()`, `is_predicting()`, `ignore_prediction(node)`,
  `get_last_known_input()` and `get_last_known_state()` are available. Reject
  input older than the initial 350 ms bound (about 11 ticks). Sanitization must
  occur in input property setters and immediately before simulation; finite,
  type/range, magnitude and owner checks remain application responsibilities.
- Autoloads installed in source order: `NetworkTime`,
  `NetworkTimeSynchronizer`, `NetworkRollback`, `NetworkEvents`,
  `NetworkPerformance`. `netfox/events/enabled = false` disables automatic
  start/stop; the application's handshake/world-ready code must call
  `NetworkTime.start()`/`stop()`. `start()` synchronizes clients asynchronously;
  await it or use `after_sync`. Server `after_sync` is immediate. Use
  `is_initial_sync_done()` and server `is_client_synced(peer_id)`.
- Tick signals: `before_tick_loop()`, `before_tick(delta,tick)`,
  `on_tick(delta,tick)`, `after_tick(delta,tick)`, `after_tick_loop()`.
  `NetworkRollback` attaches its rollback handler to `after_tick_loop` during
  its autoload `_ready`, before later application autoloads.
- Rollback phases are `before_loop`, `on_prepare_tick(tick)`,
  `after_prepare_tick(tick)`, `on_process_tick(tick)`,
  `after_process_tick(tick)`, `on_record_tick(tick+1)`, `after_loop`. It reruns
  historical ticks on the server too. `max_ticks_per_frame` limits **new** ticks,
  not rollback iterations; rollback itself is bounded by `history_limit`.
- Collect immutable per-tick movement results with a release-pinned adapter:
  synchronizer `_states.get_history(tick).as_dictionary()` yields property
  paths to values. `get_history` may use closest prior state, while
  `get_snapshot` is exact and can be empty. Reading final history after the
  complete rollback loop avoids callback connection-order assumptions.
  Commit each new tick once with its own pose, not the final batch pose; do not
  replay mobs/combat/gameplay. Never use `is_fresh` alone as a combat clock.
- `PeerVisibilityFilter` exists at `rb.visibility_filter`, with
  `add_visibility_filter(callable(peer_id))`, `set_visibility_for`,
  `default_visibility`, `update_visibility()` and modes `ON_PEER`, `PER_TICK_LOOP`,
  `PER_TICK`, `PER_ROLLBACK_TICK`, `NEVER`. Filters must always admit the owner;
  use hysteresis and deliberate low-frequency updates for non-owning peers.
- All inspected core Netfox RPCs omit an explicit channel, therefore use default
  Godot channel 0. Custom channels 8–10 do not collide with this release.
  Allocate enough channels on both ENet create methods (e.g. 16).
- Full states and input use ordered property arrays plus an 8-bit configuration
  version; diffs use `PackedByteArray` with a property bitmask. There is no
  separately configured compact-schema API in this release. Keep property
  lists/order identical on all peers. Configure complete diff recovery with
  `full_state_interval` (default 24) and `diff_ack_interval` (default 0).
  State sends are coupled to rollback records, not a made-up 20 Hz setting.
- **Redundancy gotcha:** `NetworkRollback.input_redundancy` reads the setting,
  but the installed transmitter constructs `_RedundantHistoryEncoder` with
  its own default redundancy 4 and never copies the setting. If tuning it,
  isolate a verified adapter assignment after `process_settings`, not an
  unverified assumption that project setting 3 takes effect.
- **Malformed input limitation:** upstream encoders sanitize authority, not
  all wire shapes or value ranges. They can access `pop_back()`/divide according
  to property count; enforce bounded application inputs and document the
  educational, non-commercial-anticheat scope. Do not claim hardened transport.
- `TickInterpolator` writes its configured properties during `_process` and
  restores its `_state_to` before network ticks. Never configure it on server
  logic/collision state. Interpolate separate client-only presentation.
- Core has no dedicated liveness/spawn helper. Give each life a unique actor
  path; retain retired movement actors for the history window with explicit
  spawn/retire tick guards, then free. Do not reuse the same actor for disjoint
  lifetimes or free a body whose historical ticks still need it.
- `NetworkPerformance` is enabled in debug; release needs custom feature
  `netfox_perf`, or independent counters. Its network-loop duration includes
  rollback; never add the two as if disjoint. Its clock uses wall time; use
  `Time.get_ticks_usec()` for monotonic application measurements.

## Required acceptance and metrics

Defaults are in `config/default-config.json`, copied exactly. Key rates:
players/physics 30 Hz; active mobs 15 Hz; AI 5 Hz; activation 2 Hz; mob
snapshots 10 Hz; heartbeat 1 s. Chunks 10 m; wake/sleep 45/60 m with 3 s grace;
AOI 65/80 m; interpolation/extrapolation 100/100 ms. Weapon 35 m, 6 shots/s,
25 damage; lag rewind <=250 ms with 500 ms hitbox history. Payload target 900 B.

Run actual ENet server plus two clients/bots, readiness timeout and owned-PID
cleanup. Verify movement/collision and no duplicate rollback motion; 4 hits
kill once; walls/range/cadence; zombie attacks, HP, death, safe respawn and
old-life rejection; dormancy retains ID/HP/pose with zero dormant movement,
AI/navigation; two separated players keep union activity and per-peer AOI;
late join, reconnect, heartbeat, partial/lost/out-of-order snapshots and
interest epochs/tombstones; GUI controls/Escape/F3; exported binary startup.
Add independent protocol, math-geometry and malicious-intention invariants.

Network adversity: localhost, measured ~100 ms RTT with 2% packet loss, then
~150 ms RTT with 5% loss and 20 ms jitter. Prefer a controlled local UDP proxy:
no extras were installed, and editor-only network simulation is not proof of
headless/export behavior. Measure resulting RTT, not only configured delay.

Each benchmark is 10 s warmup + 60 s observed measurement; required A–H:
0 players/0 mobs; 1 player/0 mobs; 1/20 active; 1/20 dormant; 1/100 dormant;
4/50 active; 2 split groups; 2/20 combat. Optional I: 1/1000 dormant.
Keep active populations stable in noncombat scenarios and report observed
counts. Use a unique run_id per repetition.

JSONL `tick`: `kind`, `run_id`, `scenario`, `elapsed_s`, `tick_ms`,
`rollback_ms`, `rollback_ticks`; tick_ms is the wall-clock instrumented
simulation work (boundaries declared in metadata), not configured delta or
idle time. `sample` each second: same shared fields, `cpu_core_percent`,
`rss_mb` (MiB), `players`, `active_mobs`, `dormant_mobs`, `relevant_mobs`,
`tx_bytes_s`, `rx_bytes_s`, `dormant_movement_steps`, `dormant_ai_steps`,
`dormant_navigation_steps` (cumulative). CPU 100% = one core; network scope
must declare application payload versus full ENet traffic. Buffered benchmark
logging only, monotonic scenario timestamps, no example numbers as results.

Run `python3 scripts/summarize_metrics.py logs/benchmark.jsonl --warmup 10
--duration 60 --csv results/benchmark.csv --markdown results/benchmark.md`.
It computes nearest-rank percentiles and only returns PASS_DORMANCY when
actual dormant mobs and all three zero counters are present. p95 <16.7 ms
is an initial margin goal, not a VPS capacity certification.
